## #️⃣ **문제: DB연결 실패**

> **문제상황**  
> **1.** DB 연결을 로컬에서 마치고 배포까지 완벽하게 했다고 자부한 **엄준식 씨**.  
> **2.** 그는 배포된 도메인에 접속해 **DB 연결 성공을 확인하고 꿀잠에 들었다.**  
> **3.** 그리고 다음 날 아침, 엄준식 씨를 기다리고 있는 건 무수한 팀원들의 카톡 질타였다.  
> **4.** **"준식 씨.. 화면에 Network Error만 뜨는데요?"**  
> **5.** 그럴 리 없다고 생각한 엄준식 씨가 황급히 **본인의 브라우저로 접속해 보니 너무나 정상 작동을 하는 게 아닌가.** 나한테만 되고 남한테는 안 되는 이 억울한 상황... 과연 어떤 문제가 있던것일까?

### **원인 분석**
> 준식 씨는 AI의 조언만 믿고 약 3시간 동안 AWS 인프라와 씨름했으나, 문제는 전혀 해결되지 않았다..  
> 결국 그는 눈물을 머금고 처음부터 다시 문제를 분석해 보기로 했다.

1. **내 컴퓨터**에서 배포된 도메인으로 접속하면 DB 값들이 잘 보여진다.
2. **팀원들의 컴퓨터**에서 배포된 도메인으로 접속하면 `Network Error`가 나타난다.
3. **네트워크 탭을 열어본 준식 씨는 경악을 금치 못했다.**

### **범인은 바로 '자기중심적 사고' (localhost)**
준식 씨가 겪은 이 기이한 현상의 원인은 바로 `localhost`**라는 주소의 함정** 때문이었다.  

**문제의 코드** `apiClient.js`
```js
import axios from 'axios';

// 백엔드 API의 기본 주소
const BASE_URL = 'http://localhost:8000/api';

const apiClient = axios.create({
  baseURL: BASE_URL,
  headers: {
    'Content-Type': 'application/json',
  },
});

export default apiClient;
```

- **준식씨의 상황 (성공):**
    * 준식 씨의 컴퓨터에는 백엔드 서버가 8000번 포트에서 열심히 돌고 있었다.
    * 브라우저가 localhost:8000으로 요청을 보내면, **준식 씨 컴퓨터 내부**의 백엔드를 찾아가니 당연히 성공한다.

- **팀원들의 상황 (실패):**
    * 팀원 A가 본인의 집에서 배포된 사이트에 접속한다.
    * 프론트엔드 코드가 팀원 A의 브라우저에서 실행되며 `localhost:8000`으로 데이터를 요청한다"
    * 팀원 A의 컴퓨터(localhost) **8000번 포트에는 아무것도 없다.** (당연함, 백엔드 서버는 AWS에 있음)
    * 결국 브라우저는 허공에 삽질을 하다 `Network Error`를 뱉어낸 것..

### **해결방안**
이 문제를 해결하려면 apiClient.js의 B**ASE_URL을 상대 경로로 변경**해야 한다.  

또한 `admin/backend/app/main.py` 파일에는 FastAPI 백엔드가 `/api` 라우터를 포함하고 동시에 프론트엔드 파일도 함께 서빙하고 있다. 즉, 프론트엔드와 백엔드 API가 같은 도메인에서 서비스 되기 때문에 `BASE_URL`을 localhost 대신 상대 경로인 `/admin`로 변경하면 된다.

**수정 전**:
```js
const BASE_URL = 'http://localhost:8000/api';
```
**수정 후**:
```js
const BASE_URL = '/admin';
```

> 사실 상대경로 **/api** 로 먼저 고쳤다가 **503에러**가 떠서 이 또한 해결하기 위해 엄준식씨는 눈물을 흘리며 오류를 고쳤지만, 503에러가 떴다는것은 **최소한 DB연결은 성공했다는 뜻으로 만족**했다고 한다..
