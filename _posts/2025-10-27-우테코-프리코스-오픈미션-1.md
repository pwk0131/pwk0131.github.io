## **서론**
이번 미션에서 핵심으로 제시된 **새로운 시도**라는 조건은 나에게 오히려 하나의 **제약**처럼 다가왔다. 겉보기에는 가볍게 들릴 수 있는 표현이지만, 단순히 새로운 방식이나 기술을 시도하는 데 그치는 것이 아니라, 그 시도를 통해 어떤 배움과 성장을 가져갈 수 있을지 깊이 고민해야 비로소 의미 있는 **새로운 시도**가 된다고 느꼈기 때문이다.

그동안 진행했던 프로젝트들에서의 내 역할은 백엔드와 프론트엔드 기능 구현에 초점이 맞춰져 있었다. 반면, 프로젝트를 지탱하는 **인프라 전반**, 예를 들어 **`아키텍처 설계`**, **`데이터베이스 구조화`**, **`배포`**, **`CI/CD 파이프라인 구축`** 등은 직접 경험해볼 기회가 없었다. 그래서 이번 미션에서는 이러한 **인프라 구축 전반을 스스로 설계하고 구현해보는 경험을 새로운 시도로 삼고자 했다.**

| 구분 | 기존 경험 | 새로운 시도(이번 미션) | 시도 목적 | 기대 효과 |
|---|---|---|---|---|
| 개발 영역 | 백엔드 / 프론트엔드 기능 구현 중심 | 인프라 전반 설계 및 구축 | 서비스 전체 구조 이해 확장 | 단순 기능 구현을 넘어 **서비스 아키텍처 관점** 확보 |
| 아키텍처 | 단일 서버 기반 혹은 기본 구조 사용 | 서비스 구조를 스스로 설계 | 구성 요소 간 역할과 책임 명확화 | 유지보수성과 확장성 향상 |
| 데이터베이스 | 단순 테이블 설계 및 쿼리 작성 | 스키마 전략, 인덱싱, ERD 설계 고려 | 데이터 흐름 이해 및 성능 고려 | 데이터 구조에 대한 **근본적 이해** 향상 |
| 배포 | 로컬 환경 / 간단한 배포 경험 | 클라우드 환경에서 배포 자동화 | 실제 서비스 운영 관점 습득 | 운영 안정성과 자동화 경험 축적 |
| CI/CD | 사용 경험 없음 | 파이프라인 구축 및 테스트 자동화 | 협업과 배포 과정의 효율화 | 개발 흐름 전반의 **자동화 및 품질 관리** 체계화 |
| 학습 방식 | 필요한 기능 위주로 학습 | 설계 → 구현 → 운영까지 전 과정 수행 | 전체 개발 라이프사이클 경험 | 개발자로서의 **시야 확장 및 성장** |

> 현재 이 블로그 글을 쓰고 있는 이후부터 경진대회를 준비해야하기 때문에.. 기능구현에 대한 것은 일주일 뒤가 아닐까..  

> 간략한 계획 | ~11.07 (외부일정) | 11.08 ~ 11.09 (기획) | 11.09 ~ 11.12 (구현) | ~ 11.16 (배포)

## **기획**
1. 인프라 구축에 대한 주제이기 때문에, 기능구현은 익숙한 언어 `JAVA(Spring)` + `React` 를 사용하며, 기능구현에 힘을 쓰지 않는다.
  - **주제**: 특정 웹사이트의 현재 상태("UP", "DOWN")와 **응답 시간(ms)을 보여주는 대시보드**
  - **아키텍처**: Java 백엔드에서 1분마다 특정 사이트들의 상태를 체크하는 스케줄링 작업을 구현
  - **DB**: 시계열 데이터를 다루는 간단한 경험
  - **배포(AWS)**: 백그라운드 스케줄러가 포함된 Java 앱을 Docker로 띄우고, React 앱이 이 백엔드의 API를 주기적으로(예: 10초마다) 호출하여 화면을 갱신하는 구조를 완성도 있게 배포
2. 설계하려는 인프라 구성 요소들과 의미 있게 상호작용할 수 있는 주제를 구상한다.
3. 만약 동업자가 생긴다면 어떤 환경에서든 동업할 수 있도록 구상하며 진행한다.
