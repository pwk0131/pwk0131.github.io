## #️⃣ **로그인 로직 & 보안강화 계획**
![구글로그인](/assets/img/WTC/open/open_mission_3/OAuth 2.0.png)

**관리자 페이지**는 Google OAuth 2.0을 통해 사용자를 1차 인증하고, 백엔드에서 **허용된 이메일(Whitelist)**인지 검증한 후 자체 **JWT(Access Token)**를 발급하여 세션을 유지하는 방식으로 로직을 짰다.

즉. 전체적인 인증 흐름은 크게 **프론트엔드 요청** → **백엔드 검증 및 토큰 발급** → **API 요청 인터셉터**의 **3단계**로 나뉜다.

### 1. **프론트엔드: Google 로그인 트리거**
로그인 페이지에서는 `@react-oauth/google` 라이브러리를 사용하여 Google 로그인을 구현했다. 사용자가 구글 로그인을 완료하면 `id_token`을 받아 백엔드로 전송한다.

- **토큰 전송**: 구글 인증 성공 시 반환되는 `credentialResponse.credential`(Google ID Token)을 `/auth/google/login` 엔드포인트로 전송한다.

- **토큰 저장**: 백엔드로부터 응답받은 자체 `access_token`을 `localStorage`에 저장하고, `apiClient`의 기본 헤더에 설정하여 이후 요청 시 자동으로 인증 정보가 포함되도록 한다.

```js
// Login 핵심 로직
const handleGoogleSuccess = async (credentialResponse) => {
  const id_token = credentialResponse.credential; // Google ID Token
  
  // 백엔드 검증 요청
  const response = await apiClient.post('/auth/google/login', {
    id_token: id_token
  });

  // 서비스 전용 토큰 저장
  const { access_token } = response.data;
  localStorage.setItem('admin_token', access_token);
  apiClient.defaults.headers.common['Authorization'] = `Bearer ${access_token}`;
  navigate('/', { replace: true });
};
```
### 2. **백엔드: 토큰 검증 및 권한 확인**
백엔드(FastAPI)는 프론트엔드에서 받은 **Google ID Token**을 검증하고, **해당 사용자가 관리자 권한이 있는지 확인**한다.

- **Google 토큰 검증**: `google.oauth2.id_token.verify_oauth2_token`을 사용하여 토큰의 유효성을 검사하고 이메일 정보를 추출한다.

- **관리자 권한 확인 (Whitelist)**: 추출된 이메일이 환경 설정(`settings.ALLOWED_ADMIN_EMAIL`)에 등록된 관리자 이메일과 일치하는지 확인하고, 일치하지 않을 경우 `403 Forbidden` 에러를 반환하여 접근을 차단한다.

- **자체 JWT 발급**: 검증이 완료되면 create_access_token 함수를 통해 서비스 전용 JWT를 생성하여 클라이언트에 반환한다.
```python
# auth 핵심 로직
@router.post("/auth/google/login")
async def google_login(token_data: GoogleToken):
    # 1. 구글 토큰 검증
    idinfo = id_token.verify_oauth2_token(token_data.id_token, ...)
    email = idinfo.get('email')

    # 2. 허용된 관리자 이메일인지 확인
    if email != settings.ALLOWED_ADMIN_EMAIL:
        raise HTTPException(status_code=403, detail="Access denied")
            
    # 3. 자체 액세스 토큰 발급
    app_access_token = create_access_token(email=email)
    return {"access_token": app_access_token, ...}
```
### 3. **API 클라이언트: Axios Interceptor 활용**
로그인 이후의 모든 **API 요청에 대해 인증 상태를 유지**하고, 토큰 만료 시 **자동으로 로그아웃 처리**를 수행하기 위해 Axios Interceptor를 설정했다.

```js
// apiClient 핵심 로직
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('admin_token');
  if (token) {
    config.headers['Authorization'] = `Bearer ${token}`;
  }
  return config;
});

apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response && error.response.status === 401) {
      localStorage.removeItem('admin_token');
      window.location.href = '/admin/login'; // 강제 로그아웃
    }
    return Promise.reject(error);
  }
);
```

즉, **서버 측 Whitelist를 검증**하여 **인가된 관리자만 접근**할 수 있도록 로직을 구현하였다.  
그러나, 로직을 짜고 보니 **localStorage로 토큰을 관리하는 방식에 불안감**이 생기기 시작했다.  

> **위험 사항**  
> **1.** XSS(Cross-Site Scripting) 공격에 취약함  
> **2.** HttpOnly 및 Secure 속성 사용 불가  
> **3.** 브라우저에 저장됨
{: .prompt-warning }

만약 관리자 페이지에서도** XSS 취약점이 발견된다면?** `localStorage`에 있는 토큰은 **해커에게 문을 열어주는 프리패스권**이 될 것이다.  

### 4. **개선할 점**

계획한 보안강화 로직으로는 **LocalStorage -> HttpOnly Cookie 방법**이다.

> **계획**  
> **1.** 백엔드의 로그인 응답(auth.py)에서 **Set-Cookie** 헤더를 사용해 토큰을 전달  
> **2.** 프론트엔드는 별도의 저장 로직 없이 쿠키를 자동으로 전송하도록 **withCredentials: true** 옵션을 사용.  
{: .prompt-tip }

> 회고글을 모두 작성하고 적용해볼 예정이다.

## #️⃣ **마무리: FastAPI**

마무리로는 **FastAPI를 사용해본 후기**를 말해보려한다.  

결론부터 말하자면, 우려했던 **FastAPI와 Python 사용 자체에는 큰 어려움이 없었다.** 물론 익숙치 않은 문법 탓에 오타를 내거나 자잘한 시행착오도 많았지만 기억에 남는 큰 오류는 없었다.

오히려 `Spring Boot`와 비교했을 때, `FastAPI`는 거추장스러운 설정 없이 직관적으로 코드를 짤 수 있어 **가볍고 빠르다**는 장점을 확실히 체감할 수 있었다. 심지어 짧은 개발 기간안에 적용할만한 **장점**또한 보였다.

**간단한 GET 요청 + 쿼리 파라미터 받기**  

**Spring Boot (Java)**
```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public HelloResponse hello(@RequestParam String name) {
        return new HelloResponse("Hello, " + name);
    }
}
// DTO 클래스 별도 필요
@Getter @AllArgsConstructor
class HelloResponse { private String message; }
```  

**FastAPI (Python)**
```python
from fastapi import FastAPI

app = FastAPI()

# 직관적이고 짧음
@app.get("/hello")
async def hello(name: str):
    return {"message": f"Hello, {name}"} 
    # DTO 없이 dict만 리턴해도 자동 JSON 변환
```

### **새로운 시도와 몰입은 코드 밖에 있었다**

사실, **FastAPI를 사용하면서 문법적인 난관에 부딪힌 적은 거의 없다.** 요즘 개발 트렌드인 AI 툴의 도움을 적극적으로 받았고, 덕분에 소위 말하는 **'바이브 코딩(Vibe Coding)'**을 통해 물 흐르듯 기능을 구현할 수 있었기 때문이다.

하지만 아이러니하게도, 언어의 장벽이 낮아지니 **'환경의 장벽'**이 보이기 시작했다.
앞선 문제 해결 파트에서 언급했듯, 나의 발목을 잡은 건 Python 문법이 아니라 **DB 연결, 비동기 처리의 이해, 배포 환경의 변수 설정** 등이었다. Spring이라는 거대한 프레임워크가 알아서 해주던 것들을 내 손으로 직접 조립해야 했기 때문이다.

처음에는 *"단순히 언어만 바꾼 것이 과연 미션에서 요구한 '새로운 시도'일까?"* 라는 아쉬움도 있었다. 거창한 아키텍처나 신기술을 도입한 것은 아니었기 때문이다.

하지만 돌이켜보면, 익숙한 Spring의 울타리를 벗어나 **낯선 도구를 들고 맨땅에서 발생한 오류들과 직면했던 그 시간들**. 비록 의도했던 형태는 아니었을지라도, 그 과정 하나하나가 나에게는 무엇보다 **값진 '새로운 시도'**였다고 확신한다.

### **진짜 마무리**

**우아한테크코스 프리코스의 막이 이렇게 내렸다.** 오픈 미션 설명회 당시 **'몰입'**이라는 키워드를 설명하며, **'바리스타 자격증 취득도 몰입의 일환'**이라는 예시를 들었던 것이 기억난다. 솔직히 말하자면, 당시엔 조금 황당했다. 개발자를 양성하는 곳에서 개발과 무관해 보이는 예시라니. 결국 개발자는 코드로 문제를 해결할 때 비로소 의미가 있는 것이라 생각했기 때문이다. 

그러나, 현재 나 또한 학교 **챗봇의 개발을 우테코 오픈미션과 엮어서 제출을 한다는게**, 사실 **바리스타 자격증을 따는 것과 다를게 없지 않을까 하는 불안감**과, 그럼에도 2주간 실제 서비스 배포를 위해 빠른기간 낯선 도구를 활용하여 백엔드 개발을 해본 **이 경험이 실제로 몰입**이 되었다. 오픈미션 뿐만 아니라 **실제 인생에서의 몰입** 말이다.

오픈미션을 진행하며 깨달은 점이라면 '무엇을 하느냐'보다 **'어떻게 빠져드느냐'**였다. 실제로 문제해결에 관한 내용을 평소보다 자세하게 적었으며 이것을 적는 재미도 있었다. 이러한 경험이 생기며 이번 오픈 미션은 나에게 단순한 개발 경험을 넘어, **몰입**이란 단어에 다시한번 생각해보게 하는 기간이었다.

> 오픈미션을 진행하는 우테코 여러분, 그리고 코치, 관리자 여러분 모두 고생하셨습니다.
